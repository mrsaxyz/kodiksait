# Учебный модуль CodeSlicer для ЛР № 3–6

## Запуск

Требуется Node.js 18+ и npm. Из каталога `lab03-06`:

```powershell
npm run build
npm test
npm start
```

Затем откройте:

| ЛР | URL | Что показывать |
|---|---|---|
| 3 | http://127.0.0.1:8001/lab03/ | Mock-массив, фильтр, карточки, подробности, дублирование, удаление; **«Домой» в шапке**. В DevTools → Network показать GET index.html и Response. |
| 4 | http://127.0.0.1:8001/api/projects | JSON API, пять методов в Postman, локальный файл `projects.json`. |
| 5 | http://127.0.0.1:5500/lab05/ | Кросс-доменный `XMLHttpRequest`: сначала CORS-ошибка, затем запрос после разрешения в браузере; форма без «Сохранить». |
| 6 | http://127.0.0.1:8001/ | Fetch, async/await, POST/PUT/DELETE, один JS `bundle.js` в Sources, API с того же origin. |

### ЛР4 — Postman

Импортируйте `postman/CodeSlicer-Lab04.postman_collection.json` в Postman. Коллекция содержит: `GET` с фильтром, `GET /:id`, `POST`, `PUT /:id`, `DELETE /:id`. **Сначала выполните POST**, он запишет ID созданного проекта в переменную `createdId`; затем можно показывать GET/PUT/DELETE. Для финальной фильтрации снова запустите первый GET, изменив параметр `search`.

`npm test` проверяет HTTP CRUD на временной копии `projects.json`, поэтому не меняет демонстрационные данные.

### ЛР5 — два разных сервера и CORS

При запущенном Node-сервере в **другом PowerShell** из `lab03-06` выполните:

```powershell
python -m http.server 5500 --bind 127.0.0.1
```

Откройте `http://127.0.0.1:5500/lab05/` (не порт 8001). На этой странице запрос идёт на `http://127.0.0.1:8001/api/projects`: разные порты → разные origin → браузер блокирует ответ без заголовка `Access-Control-Allow-Origin`. Согласно методичке продемонстрируйте разрешение запроса через **CORS Unblock** и повторную фильтрацию. Для локальной технической проверки есть альтернатива: перезапустить Node с разрешённым CORS:

```powershell
$env:ENABLE_CORS='1'; npm start
```

Для лабораторной №6 выключите расширение и перезапустите сервер обычным `npm start`: и страница, и API в ЛР6 живут на `127.0.0.1:8001`.

### ЛР6 — сборка

`npm run build` объединяет **два** JS-исходника в `lab06/dist/bundle.js` без внешних зависимостей. Это минимальный собственный учебный bundler, а не полноценный Webpack/Vite. На странице подключён только `bundle.js`, исходники доступны в репозитории отдельно. В DevTools → Sources проверьте, что страница загрузила bundle, а не `src/app.js` и `src/api.js`.

```text

│   └── dist/       # сборка (по методичке — ветка ЛР4)

├── tests/          # автоматические тесты API
├── report.pdf

```

## Перед защитой: обязательные условия методички

1. В методичке `iu5git/JavaScript` требуется **отдельная Git-ветка для каждой ЛР**. Архив пока содержит общую учебную реализацию для удобного запуска и выгрузки; отдельные ветки нужно создать перед защитой.
2. **Ветка ЛР5 содержит только frontend** (backend запускается отдельно из ветки ЛР4). **Ветка ЛР6 содержит только исходники frontend**, а собранный `bundle.js` размещается в ветке ЛР4.
3. Также методичка требует тему **«услуги и заявки»**. В представленном учебном варианте основная CRUD-сущность пока называется «проект». До окончательной сдачи необходимо согласовать предметную область с преподавателем и при необходимости расширить модель до «услуг анализа» и «заявок на анализ».
4. В отчёте пока используются иллюстративные экранные формы. Для защиты откройте реальные страницы и сделайте снимки из браузера/DevTools/Postman. Не представляйте их как реальные снимки, пока они не заменены.
